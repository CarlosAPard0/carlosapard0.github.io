### Problem Context
A retail client requires a daily report to monitor business performance, tracking key metrics such as total purchases (`total purchase`) and gross revenue generated (`total revenue`) per day.

Transactional data does not reside in a centralized repository; instead, it is continuously generated by an external REST API in JSON format. This API emits heterogeneous events covering purchases (`purchase`), cancellations (`cancel`), and refunds (`refund`). To structure and ensure data quality in a scalable manner, a **Medallion Architecture** (*Bronze*, *Silver*, and *Gold*) was implemented in Azure, enabling progressive data refinement.

### Tech Stack and Architectural Decisions
- **Azure Data Factory (ADF) / Synapse Data Pipelines:** Orchestration and ingestion from the REST API (via HTTP connector) into Azure Data Lake Storage Gen2 (ADLS Gen2). Explicit mapping of the `amount` field to `Double` was configured to prevent type conversion errors during raw ingestion.
- **Azure Data Lake Storage Gen2 (ADLS Gen2):** Hierarchical storage structured into three tiers (`bronze`, `silver`, `gold`) to physically isolate data based on its refinement level.
- **Azure Synapse Analytics (Spark Pools & PySpark):** Distributed compute engine handling large-scale data processing:
  - *Silver Layer:* Filtering for `purchase` transaction events, removing records with null values in `customer_id` and `amount`, standardizing dates via `to_date()`, lowercasing payment methods, and casting amounts to float.
  - *Gold Layer:* Business aggregation via `groupBy("event_date")` to compute daily revenue (`daily_revenue`) and total purchase count (`total_purchase`).
- **Synapse Serverless SQL Pool:** Creation of a relational database (`retail_PC`) and an external SQL table or view over the Gold layer Parquet files. This exposes prepared metrics through standard SQL queries for efficient consumption by data analysts and data scientists.

### Architecture and Results
The end-to-end data pipeline runs within Azure Synapse Analytics:

1. **Ingestion (Bronze):** ADF extracts JSON data from the REST API and stores it in the ADLS Gen2 `bronze` container in Parquet format, preserving an immutable record of the raw source.
2. **Data Cleaning and Hygiene (Silver):** The PySpark job reads the Bronze layer, discards cancellations and refunds, cleans null values, applies uniform formatting, and writes validated transactions to the `silver` layer.
3. **Business Aggregation (Gold):** A second PySpark script aggregates metrics by date and writes the output to the `gold` layer in Parquet format.
4. **Serving Layer (SQL Layer):** Through external tables in Synapse Serverless SQL Pool, consolidated data becomes immediately available for SQL queries without incurring fixed storage costs or requiring dedicated infrastructure.

- **Enforced data quality:** Elimination of transactional noise and full schema hygiene in the Silver layer prior to any aggregation.
- **Optimized storage:** Consistent use of the Parquet format starting from the Bronze layer to maximize compression and improve query read performance.
- **Analytics readiness:** Data fully structured and prepared in a low-cost SQL serving layer, ready for advanced analytics and downstream machine learning models.
